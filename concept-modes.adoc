= Erfahren Sie mehr über die Bereitstellungsmodi der NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Sie können NetApp Console über die SaaS-Anwendung nutzen oder sie selbst in Ihrer eigenen Umgebung (Cloud oder On-Premises) installieren.

NetApp bezeichnet diese Anwendungsfälle als _Bereitstellungsmodi_. Jeder Modus bietet unterschiedliche Konnektivität, Funktionen und Dienste für Ihre Geschäfts- und Sicherheitsanforderungen.

Standardmodus (SaaS):: Die NetApp Console SaaS (Software-as-a-Service)-Anwendung ermöglicht den Zugriff auf alle NetApp Datenservices, automatisierte Updates und flexible Authentifizierungsoptionen wie Identitätsföderation und NetApp Support Site-Anmeldungen. Dieser Modus unterstützt Marketplace-Abonnements und BYOL-Lizenzierung. Dieser Modus ist ideal für die meisten Benutzer und Organisationen, insbesondere für diejenigen, die die meisten Funktionen und Services nutzen möchten, die mit der NetApp Console verfügbar sind.
Eingeschränkter Modus (in Ihrer eigenen öffentlichen Cloud installiert):: Der eingeschränkte Modus ist für Organisationen mit erhöhtem Sicherheitsbedarf und begrenzter Konnektivität vorgesehen, beispielsweise Regierungen und regulierte Unternehmen. Sie installieren die NetApp Console in Ihrer eigenen öffentlichen Cloud (in einer Regierungs-, souveränen oder kommerziellen Region), und sie hat eine eingeschränkte ausgehende Konnektivität zu den NetApp Console API-Endpunkten (gehostet in der SaaS-Anwendung). Der eingeschränkte Modus bietet Zugriff auf wichtige Datendienste wie Cloud Volumes ONTAP, Azure NetApp Files, NetApp Backup and Recovery (in Regierungs- und kommerziellen Regionen) sowie Datenklassifizierung, zusammen mit automatisierten Software-Upgrades und Identitätsföderation.
Privater Modus (installiert vor Ort oder in der Cloud):: Der private Modus ist für Organisationen mit strengen Sicherheitsanforderungen geeignet, wie beispielsweise in AWS Secret Cloud, AWS Top Secret Cloud, Azure IL6 oder abgeschotteten Umgebungen. Er stellt keine Verbindung zur NetApp Console SaaS-Anwendung oder NetApp Cloud-basierten APIs her, wodurch Sie die volle Kontrolle haben und die externe Kommunikation blockiert wird. Unterstützte Datendienste umfassen NetApp Backup and Recovery, NetApp Data Classification, NetApp Replication und Cloud Volumes ONTAP. Alle Speicherung und Authentifizierung bleiben lokal, sodass die Daten innerhalb Ihrer Umgebung verbleiben. Verwenden Sie diesen Modus für Rüstungsunternehmen, Finanzinstitute mit strengen Datenresidenzregeln und Regierungsbehörden mit klassifizierten Systemen.



NOTE: NetApp Console beschränkt den Datenfluss in eingeschränkten und privaten Modi, aber Sie müssen sicherstellen, dass Ihre Umgebung Ihren Vorschriften entspricht.

Jeder Bereitstellungsmodus unterscheidet sich hinsichtlich ausgehender Konnektivität, Standort, Installation, Authentifizierung, Datendiensten und Abrechnungsmethoden.

=== Funktionsweise der NetApp Console im Standardmodus

Die Konsole funktioniert im Standardmodus wie folgt:

Ausgehende Kommunikation:: Für den täglichen Betrieb ist eine Verbindung von einem Agenten zur Console SaaS-Anwendung, zu den öffentlich verfügbaren Ressourcen Ihres Cloud-Anbieters und zu anderen wichtigen Komponenten erforderlich.
+
--
* link:task-install-agent-aws-console.html#networking-aws-agent["Endpunkte, die ein Agent in AWS kontaktiert"]
* link:task-install-agent-azure-console.html#networking-azure-agent["Endpunkte, die ein Agent in Azure kontaktiert"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["Endpunkte, die ein Agent in Google Cloud kontaktiert"]


--
Unterstützter Standort für einen Console-Agenten:: Im Standardmodus können Sie einen Console-Agenten in der Cloud oder auf Ihren eigenen Systemen installieren.



NOTE: Die Installation eines Agenten in der Cloud verursacht Cloud-Nutzungsgebühren.

Upgrades des Konsolenagenten:: NetApp aktualisiert die Agentensoftware automatisch monatlich.
Zugriff auf die Benutzeroberfläche:: Sie greifen über die Console SaaS-Anwendung auf die Benutzeroberfläche zu, die über das öffentliche Internet verfügbar ist.
API-Endpunkt:: API-Aufrufe werden an den folgenden Endpunkt gesendet: \https://api.bluexp.netapp.com
Authentifizierung:: NetApp Console bietet Authentifizierung mit auth0- oder NetApp Support Site (NSS) Logins. Identitätsföderation ist verfügbar.

== NetApp Console im eingeschränkten Modus (installiert in Ihrer eigenen öffentlichen Cloud)

Sie installieren einen Console-Agenten in der Cloud (in einer Regierungs-, Staats- oder kommerziellen Region), und er verfügt nur über eine eingeschränkte ausgehende Konnektivität zu den NetApp Console-API-Endpunkten (die in der SaaS-Anwendung gehostet werden).

Benutzer greifen auf die lokale Benutzeroberfläche des Console-Agenten zu, nicht auf die SaaS-Anwendung.

Je nach den Datendiensten und Funktionen, die Sie verwenden möchten, erstellt ein NetApp Console-Organisationsadministrator zusätzliche NetApp Console-Agenten, um Daten in Ihrer Hybrid-Cloud-Umgebung zu verwalten.

=== Funktionsweise der NetApp Console im eingeschränkten Modus

Im eingeschränkten Modus funktioniert die Konsole wie folgt:

Ausgehende Kommunikation:: Ein Agent benötigt eine ausgehende Verbindung zu den NetApp Cloud-basierten APIs zur Unterstützung von Datendiensten, Software-Upgrades, Authentifizierung und Metadatenübertragung.
+
--
NetApp initiiert keine Kommunikation zu einem Agenten. Der Agent initiiert die gesamte Kommunikation und kann Daten je nach Bedarf von oder zu den NetApp APIs und Diensten abrufen oder senden.

Außerdem ist eine Verbindung zu Cloud-Provider-Ressourcen innerhalb der Region erforderlich.

--
Unterstützter Standort für einen Agenten:: Im eingeschränkten Modus installieren Sie Agenten in der Cloud: in einer Regierungsregion, einer souveränen Region oder einer kommerziellen Region.
Upgrades des Konsolenagenten:: NetApp Console aktualisiert die Agentensoftware automatisch jeden Monat.
Zugriff auf die Benutzeroberfläche:: Benutzer greifen von einer Agenten-VM, die in Ihrer Cloud-Region bereitgestellt ist, auf die NetApp Console zu.
API-Endpunkt:: API-Aufrufe werden an eine Agenten-VM gesendet.
Authentifizierung:: Die Authentifizierung erfolgt über den Cloud-Dienst der NetApp Console mittels auth0. Identitätsföderation ist ebenfalls verfügbar.




=== Erste Schritte mit dem eingeschränkten Modus

Sie müssen den eingeschränkten Modus aktivieren, wenn Sie Ihr NetApp Console-Konto erstellen. Wenn Sie keine Organisation haben, werden Sie beim ersten Anmelden an Ihrem installierten Console-Agenten aufgefordert, eine zu erstellen und den eingeschränkten Modus zu aktivieren.

Beachten Sie, dass die Einstellung für den eingeschränkten Modus nach der Erstellung der Organisation festgelegt ist. Sie können den eingeschränkten Modus später nicht aktivieren oder deaktivieren. link:task-quick-start-restricted-mode.html["Erfahren Sie, wie Sie mit dem eingeschränkten Modus beginnen"].



== NetApp Console im privaten Modus

Im privaten Modus installieren Sie einen Console-Agenten entweder lokal oder in der Cloud und verwenden NetApp Console, um Daten in Ihrer Hybrid-Cloud zu verwalten. Es besteht keine Verbindung zu den NetApp Console API-Endpunkten oder der NetApp Console SaaS-Anwendung, daher greifen Sie über die lokale Benutzeroberfläche des Console-Agenten auf die Console zu.

=== Wie die NetApp Console im privaten Modus funktioniert

NetApp Console funktioniert im privaten Modus wie folgt:

Ausgehende Kommunikation:: Für die Console SaaS-Anwendung (wo zusätzliche API-Endpunkte vorhanden sind) ist keine ausgehende Verbindung erforderlich. Alle Pakete, Abhängigkeiten und wesentlichen Komponenten sind mit dem Console Agent gebündelt und werden vom lokalen Rechner bereitgestellt. Eine Verbindung zu den öffentlich verfügbaren Ressourcen Ihres Cloud-Anbieters ist nur erforderlich, wenn Sie Cloud Volumes ONTAP bereitstellen.
Unterstützter Standort für den Console-Agenten:: Im privaten Modus wird der Console agent in der Cloud oder vor Ort unterstützt.
Upgrades des Konsolenagenten:: Sie müssen die Console-Agent-Software manuell aktualisieren. NetApp veröffentlicht die Console-Agent-Software in undefinierten Abständen auf der NetApp Support-Website.
Zugriff auf die Benutzeroberfläche:: Benutzer greifen von dem Console-Agent, der in Ihrer Cloud-Region oder vor Ort bereitgestellt ist, auf die Console zu.
API-Endpunkt:: API-Aufrufe werden an die virtuelle Maschine des Console-Agenten gesendet.
Authentifizierung:: Die Authentifizierung erfolgt über die lokale Benutzerverwaltung und den lokalen Zugriff. Die Authentifizierung erfolgt nicht über den Cloud-Dienst der NetApp Console.
