= Erfahren Sie mehr über NetApp Console -Agenten

:allow-uri-read: 
:nofooter: 
:icons: font

[role="lead"]
Sie aktivieren die NetApp Console-Funktionen, indem Sie Konsolenagenten bereitstellen – schlanke Softwarekomponenten, die eine sichere Verbindung zwischen Ihren lokalen und Cloud-Speichersystemen und der NetApp Console herstellen und so eine erweiterte Speicherorchestrierung und Datendienste ermöglichen.



== Was ein Console-Agent tut

Ein Console-Agent überbrückt die Netzwerklücke zwischen Ihren Speichersystemen und der NetApp Console. Er verbindet Ihre Infrastruktur sicher mit den NetApp APIs und der Console und ermöglicht Ihnen Folgendes:

* Entdecken und überwachen Sie Speichersysteme in AWS-, Azure-, Google Cloud- und On-Premises-Umgebungen über die NetApp Console.
* Orchestrieren Sie Speicherbereitstellungs- und Konfigurationsaufgaben auf Speichersystemen von der NetApp Console.
* Aktivieren Sie erweiterte Datenschutz- und Optimierungsdienste.
* Verknüpfen Sie Ihre Cloud-Anbieter-Zugangsdaten mit einem Console-Agenten, um die Nutzung von Cloud-Diensten sicher zu verfolgen und Bereitstellungen mit dem richtigen Abonnement zu verbinden, damit eine genaue Abrechnung und Kostenverwaltung möglich ist.




=== Agentenarchitektur

Agenten arbeiten mit schlanken Prozessen, die:

* Daten zur und von der Console SaaS-Anwendung übertragen (Standard- und eingeschränkter Modus) oder ausschließlich lokal arbeiten (privater Modus)
* Initiieren Sie die gesamte Kommunikation – die Konsole initiiert niemals ausgehende Anrufe an Agenten
* Stellen Sie über Standardverwaltungsprotokolle eine Verbindung zu Ihren Speichersystemen her
* Verwenden Sie TLS 1.3 für die sichere Kommunikation mit Cloud-Anbietern und den NetApp Console-APIs




=== Verfügbarkeit des Agenten und betriebliche Anforderungen

Console-Agenten sind eine kritische Infrastruktur für NetApp Console. NetApp Console kann kurze Ausfälle überbrücken, aber die Agenten müssen betriebsbereit und erreichbar bleiben, um einen unterbrechungsfreien Management- und Datenbetrieb zu gewährleisten. Sie sind dafür verantwortlich, Folgendes sicherzustellen:

* Agenten bleiben aktiv und laufen weiter
* Agenten haben Netzwerkverbindung zu den erforderlichen Endpunkten
* Infrastrukturausfälle werden schnell behoben
* Die Agenten-VMs werden gemäß den Empfehlungen von NetApp gewartet und aktualisiert.




== Wenn Sie einen Console Agent benötigen

Sie müssen mindestens einen Console-Agenten bereitstellen, wenn Sie Folgendes tun möchten:

* Verwenden Sie eingeschränkte oder private Bereitstellungsmodi (Console in Ihrer eigenen Umgebung installiert). Für einige Dienste sind zusätzliche Agenten erforderlich.
* Greifen Sie auf erweiterte Datendienste zu (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification und mehr).
* Cloud Volumes ONTAP Systeme verwalten.
* Führe fortgeschrittene Verwaltungsaufgaben auf lokalen ONTAP Clustern durch.
* Lizenzen nachverfolgen, Speicherzustand überwachen und Lebenszyklus-Upgrades planen.


Ohne Agenten können Sie grundlegende Speichererkennungsfunktionen nutzen und auf einen begrenzten Satz von Überwachungs- und Speicherverwaltungsfunktionen zugreifen. Die meisten Anwendungsfälle in Unternehmen erfordern jedoch einen oder mehrere operative Agenten.

link:concept-modes.html["Erfahren Sie mehr über die Bereitstellungsmodi der NetApp Console"] um zu verstehen, wann man einen Agenten benötigt und welche Funktionen Agenten ermöglichen.



== Bereitstellungsoptionen für Console-Agenten

Sie können Console-Agenten in bereitstellen:

* Amazon Web Services (standard, eingeschränkter oder privater Modus)
* Microsoft Azure (standard, eingeschränkter oder privater Modus)
* Google Cloud (standard, eingeschränkter oder privater Modus)
* Bei Ihnen vor Ort (Standard- oder Privatmodus)


Ihr Console-Bereitstellungsmodus, Ihre Speicherumgebung und Ihre Anforderungen an die Datenhoheit bestimmen, wo Sie Agenten bereitstellen. Stellen Sie mehrere Agenten in verschiedenen Umgebungen bereit, um organisatorische Trennung oder geschäftliche Anforderungen zu erfüllen.

Nach der Bereitstellung eines Agenten registrieren Sie diesen bei Ihrer NetApp Console-Organisation, um die Funktionen für diese Organisation zu aktivieren. Sie können mehrere Speichersysteme und Datendienste mit einem einzelnen Agenten verknüpfen oder mehrere Agenten in verschiedenen Umgebungen bereitstellen, um organisatorische Trennungen oder geschäftliche Anforderungen zu erfüllen.



=== Agenten für die NetApp Console SaaS-Anwendung (Standardmodus)

Setzen Sie Agenten in Ihrer Cloud oder lokal ein, um die Verbindung zur Cloud-gehosteten Console SaaS-Anwendung herzustellen. Agenten ermöglichen erweiterte Funktionen, während die Console-UI weiterhin von überall aus zugänglich bleibt.

Sie können Agenten direkt von der Console installieren, wenn Sie die SaaS-Anwendung (Standardmodus) verwenden. Sie können in AWS, Azure oder Google Cloud installieren oder manuell vor Ort auf Ihrem eigenen Linux-Host oder in Ihrer VCenter-Umgebung.

Wenn Sie einen Agenten in Ihren Räumlichkeiten installieren, können Sie die jeweiligen Cloud-Provider-Zugangsdaten verknüpfen, um die Abrechnungsintegration und Datendienste zu aktivieren.



=== Agenten für NetApp Console im eingeschränkten Modus

Sie müssen einen Agenten installieren, über den die Benutzer auf die NetApp Console zugreifen. Zusätzliche Agenten sind erforderlich, um Datendienste zu aktivieren und Speichersysteme zu verwalten.

Wenn Sie die NetApp Console im eingeschränkten Modus verwenden, installieren Sie Agenten entweder über den Marktplatz Ihres Cloud-Anbieters oder indem Sie die Software manuell auf Ihrem eigenen Linux-Host in der Cloud, vor Ort oder in Ihrer VCenter-Umgebung installieren.

=== Agenten für NetApp Console im privaten Modus (lokal oder in der Cloud ohne ausgehende Konnektivität)

Sie müssen einen Agenten installieren, über den die Benutzer auf die NetApp Console zugreifen. Zusätzliche Agenten sind erforderlich, um Datendienste zu aktivieren und Speichersysteme zu verwalten.

Installieren Sie Agenten in Ihrem Rechenzentrum oder einer abgeschotteten Umgebung. Die Agenten haben keine Verbindung zu NetApp API-Endpunkten. Alle Vorgänge bleiben lokal, mit voller Datenhoheit und Kontrolle.

=== Verwenden Sie mehrere Agenten, wenn nötig

Jeder Agent arbeitet unabhängig und kann mehrere Speichersysteme und Datendienste verwalten. Setzen Sie mehrere Agenten ein, wenn Sie Folgendes benötigen:

* Isolation nach Speichertyp oder Organisationsfunktion
* Erfüllen Sie geografische oder Netzwerksegmentierungsanforderungen
