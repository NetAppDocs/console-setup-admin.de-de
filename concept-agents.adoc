[role="lead"]
Ein Konsolenagent ist eine schlanke Softwarekomponente, die Sie in Ihrem Netzwerk installieren, um Ihre Speicherinfrastruktur mit der NetApp Console zu verbinden. Er ermöglicht erweiterte Speicherorchestrierung, Datendienste und sichere Cloud-Integration.



== Was ein Console-Agent tut

Ein Console-Agent schließt die Verbindungslücke zwischen Ihren Speichersystemen und der NetApp Console. Er verbindet Ihre Infrastruktur sicher mit den NetApp APIs und der Console und ermöglicht Ihnen Folgendes:

* Entdecken und überwachen Sie Speichersysteme in AWS-, Azure-, Google Cloud- und On-Premises-Umgebungen über die NetApp Console.
* Orchestrieren Sie Speicherbereitstellungs- und Konfigurationsaufgaben auf Speichersystemen von der NetApp Console.
* Nutzen Sie intelligente Workflows für Datenschutz und Datenmanagement.
* Verfolgen Sie die Nutzung von Cloud-Diensten sicher und verbinden Sie Bereitstellungen mit dem richtigen Abonnement für eine genaue Abrechnung und Kostenmanagement.




=== Konsolenagentenarchitektur

Agenten arbeiten mit schlanken Prozessen, die:

* Daten von und zur Console SaaS-Anwendung abrufen oder senden (Standard- und eingeschränkter Modus)
* Initiieren Sie die gesamte Kommunikation – die Konsole initiiert niemals ausgehende Anrufe an Agenten
* Stellen Sie über Standardverwaltungsprotokolle eine Verbindung zu Ihren Speichersystemen her
* Verwenden Sie TLS 1.3 für die sichere Kommunikation mit Cloud-Anbietern und den NetApp Console-APIs




=== Verfügbarkeit und Betriebsanforderungen des Konsolenagenten

Console-Agenten sind für NetApp Console unerlässlich. Agenten müssen stets betriebsbereit und erreichbar sein, um einen unterbrechungsfreien Management- und Datenservice zu gewährleisten. Sie sind dafür verantwortlich, Folgendes sicherzustellen:

* Agenten bleiben aktiv und laufen weiter
* Agenten haben Netzwerkverbindung zu den erforderlichen Endpunkten
* Infrastrukturausfälle werden schnell behoben
* Die Agenten-VMs werden gemäß den Empfehlungen von NetApp gewartet und aktualisiert.




== Wenn Sie einen Console Agent benötigen

Sie müssen mindestens einen Console-Agenten bereitstellen, wenn Sie Folgendes tun möchten:

* Verwenden Sie eingeschränkte oder private Bereitstellungsmodi (Console in Ihrer eigenen Umgebung installiert). Zusätzliche Agenten können erforderlich sein, um einige Dienste zu aktivieren.
* Greifen Sie auf erweiterte Datendienste zu (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification und mehr).
* Cloud Volumes ONTAP Systeme verwalten.
* Führe fortgeschrittene Verwaltungsaufgaben auf lokalen ONTAP Clustern durch.
* Lizenzen nachverfolgen, Speicherzustand überwachen und Lebenszyklus-Upgrades planen.


Ohne Agenten können Sie grundlegende Speichererkennungsfunktionen nutzen und auf einen begrenzten Satz von Überwachungs- und Speicherverwaltungsfunktionen zugreifen. Die meisten Anwendungsfälle in Unternehmen erfordern jedoch einen oder mehrere operative Agenten.

== Bereitstellungsoptionen für Console-Agenten

Sie können Console-Agenten in bereitstellen:

* Amazon Web Services
* Microsoft Azure
* Google Cloud
+
Um Google Cloud-Ressourcen zu verwalten, müssen Sie Ihren Agenten in Google Cloud bereitstellen. Ein lokaler Agent kann keine Google Cloud-Ressourcen verwalten.

* Bei Ihnen vor Ort (nur Standard- oder Private-Modi)


Ihr Console-Bereitstellungsmodus, Ihre Speicherumgebung und Ihre Anforderungen an die Datenhoheit bestimmen, wo Sie Agenten bereitstellen. Stellen Sie mehrere Agenten in verschiedenen Umgebungen bereit, um organisatorische Trennung oder geschäftliche Anforderungen zu erfüllen.

Sie können Agenten direkt über die Console, über Ihren Cloud-Marktplatz oder manuell in VCenter oder lokal bereitstellen. link:concept-agent-install-options.html["Vergleichen Sie die Bereitstellungsmethoden, um die richtige für Ihre Umgebung auszuwählen"].



=== Agenten für die NetApp Console SaaS-Anwendung (Standardmodus)

Setzen Sie Agenten in Ihrer Cloud oder lokal ein, um die Verbindung zur Cloud-gehosteten Console SaaS-Anwendung herzustellen. Agenten ermöglichen erweiterte Funktionen, während die Console-UI weiterhin von überall aus zugänglich bleibt.

Sie können Agenten direkt von der Console installieren, wenn Sie die SaaS-Anwendung (Standardmodus) verwenden. Sie können in AWS, Azure oder Google Cloud installieren oder manuell vor Ort auf Ihrem eigenen Linux-Host oder in Ihrer VCenter-Umgebung.



=== Agenten für NetApp Console im eingeschränkten Modus

Im eingeschränkten Modus greifen Benutzer direkt über einen installierten Agenten auf die NetApp Console zu – nicht über die cloud-basierte SaaS-Anwendung. Sie müssen mindestens einen Agenten als Zugriffspunkt für die Console installieren. Weitere Agenten sind erforderlich, um Datendienste zu aktivieren und Speichersysteme zu verwalten.

Installieren Sie Agenten vom Marktplatz Ihres Cloud-Anbieters oder indem Sie die Software manuell auf Ihrem eigenen Linux-Host in der Cloud, in Ihren Räumlichkeiten oder in Ihrer VCenter-Umgebung installieren.



=== Agenten für NetApp Console im privaten Modus (lokal oder in der Cloud ohne ausgehende Konnektivität)

Im privaten Modus greifen Benutzer direkt über einen installierten Agenten auf die NetApp Console zu. Sie müssen mindestens einen Agenten als Zugriffspunkt für die Console installieren. Weitere Agenten sind erforderlich, um Datendienste zu aktivieren und Speichersysteme zu verwalten.

Installieren Sie Agenten in Ihrem Rechenzentrum oder in einer abgeschotteten Umgebung. Die Agenten haben keine Verbindung zu NetApp API-Endpunkten, und alle Vorgänge bleiben lokal, mit voller Datenhoheit und Kontrolle.



=== Verwenden Sie mehrere Agenten, wenn nötig

Jeder Agent arbeitet unabhängig und kann mehrere Speichersysteme und Datendienste verwalten. Setzen Sie mehrere Agenten ein, wenn Sie Folgendes benötigen:

* Isolation nach Speichertyp oder Organisationsfunktion
* Anforderungen an die geografische oder Netzwerksegmentierung


Beispiel:

* In einer Multicloud-Umgebung können Sie einen Agenten in AWS und einen weiteren in Azure bereitstellen. Jeder Agent verwaltet die Cloud Volumes ONTAP Systeme in seiner jeweiligen Umgebung.
* Ein Dienstanbieter könnte eine Console-Organisation nutzen, um Dienstleistungen für Kunden bereitzustellen, und eine weitere Organisation für die Notfallwiederherstellung einer Geschäftseinheit. Jede Organisation benötigt einen eigenen Agenten.




== Upgrades des Konsolenagenten

Agenten in der Cloud werden automatisch aktualisiert, sobald sie über ausgehenden Internetzugang verfügen. Für Agenten ohne Internetzugang (privater Modus) siehe link:task-upgrade-agent.html["Upgrades des Konsolenagenten verwalten"] für Anweisungen zur manuellen Aktualisierung.
