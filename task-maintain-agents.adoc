= Wartung von NetApp Console Agent-VMs
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Damit der Agent jederzeit betriebsbereit bleibt, sollten Ihre Console Agent VMs mit aktuellen Patches versehen, korrekt dimensioniert und in gutem Zustand sein.



[[apply-operating-system-updates-to-agent-hosts]]
== Anwenden von Betriebssystemaktualisierungen auf Agent-Hosts

Um die Sicherheit des Hosts zu gewährleisten, sollten Sie auf Ihrem Agent-Host Sicherheitsupdates für das Betriebssystem und die zugehörigen Pakete anwenden.

Dies liegt in Ihrer Verantwortung als Kunde. Die Console Agent Software kann sich selbst aktualisieren, jedoch nicht das Betriebssystem oder zugehörige Pakete.


NOTE: Wenn Sie den Console Agenten in vCenter mithilfe einer OVA eingesetzt haben, ist das Betriebssystem Teil des Agenten-Images. link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["Aktualisierung des Agenten mithilfe einer ISO-Datei"^] zum Aktualisieren des Betriebssystems.

Für die Verteilung Ihres Betriebssystems sollten die Standardverfahren Ihres Unternehmens verwendet werden. Beim Einspielen von OS-Sicherheitspatches müssen die Agent-Host Services nicht angehalten werden.

Bei Agenten, die nicht über eine OVA eingesetzt wurden, muss verhindert werden, dass Docker oder Podman im Rahmen routinemäßiger Betriebssystem-Patches aktualisiert werden, um die Kompatibilität mit unterstützten Konfigurationen zu gewährleisten. Dies kann entweder durch den vorübergehenden Ausschluss von Docker oder Podman bei Updates oder durch die dauerhafte Konfiguration des Paketmanagers zum Überspringen von Docker- oder Podman-Updates erfolgen.

Im Folgenden finden Sie Beispiele, wie Sie Docker- oder Podman-Updates für verschiedene Linux-Distributionen ausschließen können. Konsultieren Sie die Dokumentation Ihrer Linux-Distribution für die aktuellsten Anweisungen zum Ausschließen von Paketen von Updates.

.Podman-Beispiel
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Docker-Beispiel
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== Größe der VM oder des Instanztyps ändern

Für eine unterdimensionierte Agenten-VM sollten CPU oder RAM erhöht werden, damit der Agent weiterhin gut funktioniert.

Wenn Sie einen Console Agent über die Console erstellen, setzt die Console bei Ihrem Cloud-Anbieter eine VM-Instanz mit einer Standardkonfiguration ein. link:reference-agent-default-config.html["Weitere Informationen zu den Standardeinstellungen des Agenten"]. Nach der Erstellung des Agenten sollten Sie nicht zu einer kleineren VM-Instanz mit weniger CPU oder RAM wechseln.

Wenn Sie Benachrichtigungen erhalten, dass Ihre Agent-VM unterdimensioniert ist, sollten Sie ein Upgrade auf eine größere VM-Instanz mit mehr CPU oder RAM in Betracht ziehen.


NOTE: Wenn der Agent in vCenter installiert wurde, erfolgt die Größenänderung der VM-Instanz mit dem Console maintenance tool. link:task-agent-vm-config.html["Informationen zum Ändern der Größe der Agenten-VM in vCenter"^].

Falls eine Erhöhung der CPU oder des Arbeitsspeichers Ihrer Agenten-VM erforderlich ist, können die Anweisungen Ihres Cloud-Anbieters oder Ihrer lokalen Virtualisierungsplattform zur Größenänderung der VM-Instanz verwendet werden. NetApp empfiehlt eine Verdopplung der aktuellen CPU- und Arbeitsspeicherzuweisung, um eine optimale Performance sicherzustellen. Die folgende Tabelle zeigt empfohlene Größenstufen, wobei jede Stufe die CPU und den Arbeitsspeicher der vorherigen Stufe verdoppelt.

[cols="1,1,1"]
|===
| Stufe | CPU (Kerne oder vCPUs) | RAM 


| Minimum | 8 | 32 GB 


| Mittel | 16 | 64 GB 


| Groß | 32 | 128 GB 
|===

== Überwachen des Agenten

Sie bleiben über Probleme mit Festplattenspeicher, RAM und CPU auf Ihrer Agent-VM informiert, damit Sie diese beheben können.

Die Konsole benachrichtigt Sie, wenn die Agent-VM fehlerhaft ist, beispielsweise bei Problemen mit Speicherplatz, RAM und CPU.  Überwachen Sie diese Benachrichtigungen im Benachrichtigungscenter in der Konsole oder konfigurieren Sie E-Mail-Benachrichtigungen.  Gelegentliche Erhöhungen des Speicherplatzes, des Arbeitsspeichers oder der CPU-Auslastung sind normal. Wenn dies jedoch häufig vorkommt, sollten Sie Maßnahmen zur Behebung des Problems ergreifen.

Beispielsweise benachrichtigt Sie die Konsole, wenn eine Agentenressource (CPU, RAM oder Festplattenspeicher) 30 Minuten lang hintereinander 90 % ihrer Gesamtkapazität überschreitet.  Wenn die Ressourcennutzung anschließend unter diesen Schwellenwert fällt, wird die Benachrichtigung im Benachrichtigungscenter als behoben (grün) angezeigt.


NOTE: Wenden Sie sich an den NetApp Support, wenn Sie Fragen zur Modifizierung Ihrer Agenten-VM haben.

link:https://docs.netapp.com/us-en/console-setup-admin/task-monitor-cm-operations.html#notification-center["Erfahren Sie mehr."^]

[[stop-and-start-the-agent-vm]]
== Stoppen und Starten der Agent VM

Beim Stoppen und Starten der Agent VM sollten die Ausfallzeiten gering bleiben, da Verwaltungs- und Datenservices davon abhängen, dass der Agent betriebsbereit bleibt.

Stoppen und starten Sie die Agent-VM bei Bedarf über die Konsole Ihres Cloud-Anbieters oder über standardmäßige Verfahren vor Ort.

link:concept-agents.html#agents-must-be-operational-at-all-times["Beachten Sie, dass der Konsolenagent jederzeit betriebsbereit sein muss"] .



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Herstellen einer Verbindung mit der Linux-VM

Der Status des Console Agent auf seiner Linux-VM lässt sich überprüfen, um zu bestätigen, dass er ausgeführt wird.

Wenn Sie eine Verbindung mit der Linux-VM herstellen müssen, auf der der Agent ausgeführt wird, verwenden Sie die Konnektivitätsoptionen Ihres Cloud-Anbieters.

AWS:: Wenn Sie die Agenteninstanz in AWS erstellen, geben Sie einen AWS-Zugriffsschlüssel und einen geheimen Schlüssel an.  Sie können dieses Schlüsselpaar verwenden, um per SSH auf die Instanz zuzugreifen.  Verwenden Sie den Benutzernamen „ubuntu“ für die EC2-Linux-Instanz.  Verwenden Sie für Agenten, die vor Mai 2023 erstellt wurden, den Benutzernamen „ec2-user“.
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["AWS Docs: Verbinden Sie sich mit Ihrer Linux-Instance"^]

--
Azurblau:: Wenn Sie die Agent-VM in Azure erstellen, geben Sie einen Benutzernamen an und wählen die Authentifizierung mit einem Kennwort oder einem öffentlichen SSH-Schlüssel.  Verwenden Sie die von Ihnen gewählte Authentifizierungsmethode, um eine Verbindung mit der VM herzustellen.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure-Dokumente: SSH in Ihre VM"^]

--
Google Cloud:: Sie können keine Authentifizierungsmethode angeben, wenn Sie einen Agenten in Google Cloud erstellen.  Sie können jedoch über die Google Cloud Console oder die Google Cloud CLI (gcloud) eine Verbindung zur Linux-VM-Instanz herstellen.
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: Verbindung zu Linux-VMs herstellen"^]
